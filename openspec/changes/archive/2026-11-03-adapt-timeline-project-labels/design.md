# Design

## Context

`StreamTimeline` currently derives stable workspace-wide project codes and renders the code plus concise planning context as one ellipsized string in every finite bar. The button already carries a complete `aria-label` and `title`, and CSS preserves truthful bar width while extending only the pointer hit area to at least 24 CSS pixels. The adaptive-label requirement must preserve those geometry and accessibility contracts.

## Goals / Non-Goals

**Goals:**

- Select the most recognizable visible project identity that the actual bar can support.
- React to bar, context, font, and viewport changes using rendered measurements.
- Keep fixed planning context separate from the adaptive name slot.
- Preserve existing bar geometry, hit targets, focus, tooltip, and accessible detail.

**Non-Goals:**

- Persisting a manually authored short project name.
- Changing generated project-code rules.
- Expanding bars, wrapping labels, increasing row height, or hiding planning context to fit a name.
- Applying adaptive labels to unscheduled chips or non-timeline project lists.

## Decisions

### 1. Measure rendered name space rather than infer it from characters

Each finite bar will render an adaptive identity slot and a separate fixed-context slot. A layout measurement compares the identity slot's available width with rendered full-name and code widths using the bar's actual typography. The full name is selected when it fits; an overflowing name is selected when the slot is at least 50% of the full-name width; otherwise the stable code is selected.

Character counts and fixed pixel breakpoints were rejected because proportional glyphs, collision-suffixed codes, responsive typography, and variable fixed context make them unreliable. CSS-only container breakpoints were rejected because they cannot distinguish a short name that fits from a long name at the same bar width.

### 2. Reserve fixed context before choosing the identity

Points, reference/prerequisite state, projected marker, blocker codes, optional/required context, and continuation state remain generated by the timeline and occupy their own context slot. Full and ellipsized name modes reserve that fixed context before selecting the identity. In code mode, the stable code receives its natural width first and context uses or truncates within the remaining space, preventing a points or state suffix from collapsing the selected code. The complete context remains in the accessible label and tooltip.

Measuring the old combined string was rejected because a long name could conceal state or cause the fitting decision to change when only suffix content changed. Letting context remain non-shrinking in code mode was rejected after narrow bars showed points while collapsing the code entirely.

### 3. Recalculate from layout and font events

A small dedicated timeline-label component will use element refs and `ResizeObserver` to update after bar or slot geometry changes. It will also remeasure after `document.fonts.ready` and font loading completion when the Font Loading API is available. State updates will be skipped when the selected mode is unchanged.

Window-width listeners alone were rejected because forecast mutations and suffix changes can resize a bar without resizing the viewport. Continuous polling was rejected as unnecessary work.

### 4. Keep semantics on the existing project control

The button remains the sole interactive element. Visible spans are presentation only; the existing complete `aria-label` and `title` remain authoritative. A data attribute will expose the selected label mode for deterministic UI verification without changing accessible output.

Adding hidden duplicate accessible text inside the button was rejected because it could conflict with the explicit accessible name.

## Risks / Trade-offs

- [Many repeated project appearances create many observers] → Keep each observer scoped to one lightweight label and disconnect it on unmount; the current Board contains a bounded number of visible bars.
- [Subpixel measurements can oscillate at a threshold] → Compare with a small tolerance and update only when the resulting mode changes.
- [Initial render briefly uses a conservative code] → Measure in a layout effect so the browser resolves the final mode before paint in normal client rendering.
- [Very narrow bars cannot visibly retain every suffix] → Preserve truthful width and complete tooltip/accessibility detail rather than inflating geometry or wrapping rows.

## Migration Plan

No data migration is required. Deploy the component and style changes together. Rollback restores code-only visible labels without affecting saved plans, forecasts, or APIs.
